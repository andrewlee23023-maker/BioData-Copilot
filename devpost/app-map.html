💡 Reusable Practice: "LLM Reasons; Python Computes"

When building AI applications for science, medicine, or mission-critical workflows, never let an LLM do math or generate statistical numbers. Instead, use the AI strictly for what it excels at: semantic understanding, mapping natural language to structured schemas, and summarizing verified data into natural language. Let deterministic code (Python, SciPy, Pandas) handle 100% of the computation.

🗺️ Key Stops in the Codebase

Stop 1: Natural Language Intent Planning

backend/agent.py > plan_analysis()

This function takes the researcher's question and dataset column metadata. It outputs a constrained JSON schema specifying the analysis (e.g. one_way_anova, treatment vs. viability, or dose trend). If an unsupported question is asked (like predicting survival), it refuses gracefully with a friendly explanation.

Stop 2: Deterministic Statistical Engine

backend/tools/stats.py > compare_groups()

Executes exact mathematical calculations using scipy.stats. Computes group means, standard deviations, standard error of the mean (SEM), F-statistics, and exact $p$-values. Every single metric shown on the results screen originates directly from this function.

Stop 3: Interactive Plotly Visualizations

backend/tools/viz.py > generate_plotly_spec()

Builds publication-grade Plotly chart configurations with custom color palettes, error bars, and distribution jitter points. The specifications are sent as JSON to the React frontend, where react-plotly.js renders them interactively.

Stop 4: Grounded Scientific Interpretation

backend/agent.py > generate_grounded_explanation()

Translates the verified Python numbers into a concise 2–3 sentence biological interpretation. It enforces strict guardrails: zero unverified numbers, mandatory non-causality disclosure, and clear labeling of synthetic demonstration data.
